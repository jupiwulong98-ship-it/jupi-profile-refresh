# 交付字段

按用户的阅读需求组织，不要求每次套同一种排版。已有事实和决定直接复用，信息少时缩短。全流程审阅可采用下面结构。

## 1. 账号任务与材料

- 这一轮的共同主任务；观看、关注和商业机会如何分别观察。
- 做过的事情、实际被问的问题、准备研究的主题，逐项写来源。
- 一个具体用户场景：任务、卡点、已试、下一步。
- 暂定定位句及证据边界。
- 对标和内容树：已有的复用；不足的给可审阅候选与明确缺口，不捏造。

## 2. 主页改前后对照

|元素|当前内容/已观察状态|建议改成什么|真实依据|待实际检查|
|---|---|---|---|---|
|名称|取用户材料或可见页面|一个推荐版及必要备选|个人识别与长期主题|可用性、小尺寸显示|
|简介|原文保留|可复制的文案|三行分别对应身份、对象问题、入口/持续内容|长度、换行、手机显示|
|头像|看到的图或未提供|具体选图标准|辨识度与真实身份|缩小检查|
|背景|看到的图或未提供|一条信息与构图建议|补充关注承诺|裁切遮挡|
|置顶|已存在的内容|认识你、方法、过程/案例如何安排|各篇具体支持什么|完整内容是否仍可用|
|近期首屏|近期作品|同一批读者的相邻任务|连续关注的理由|实际发布与排序|

名称和简介放单独的可复制区。原图未见就写未见，不评论细节。

## 3. 代表内容

逐项区分：

- 已发布、已核对可用。
- 已发布、需要补看正文/核查操作。
- 尚未制作，只是计划。

简介引用具体内容入口时，该内容必须已存在。新稿不能伪装成已发布。置顶数量以实际可用位为准。

需要补12题测试时，每题包含：内容层、形式、来源问题、材料状态、读者动作、观察信号。将需要记录后才能写的复盘放在未来，不填虚构结果。

## 4. 修改与复盘

- 修改前：原值、截图、日期、这次主要改什么。
- 修改后：读回的实际名称与简介、首屏截图、待检查的显示问题。
- 未修改：写清这是草稿，不生成假改后截图。
- 真人测试：记录主题、对象、想看的内容及原话，不替读者填结论。
- 数据：平台、作品、发布时间、观察时间；实际提供的曝光/播放/阅读/互动/关注；具体追问；实际使用、咨询与付费分别记。
- 每4篇看一次，统一口径与时长；数据不足时记录观察，不急判因果。

## 5. 实操分享或录屏材料

用户要分享过程时，整理真实输入、使用的提示要求、实际输出、人工选择、修改前后与未验证项。只有实际改完并读回后，才使用“我已经把主页改了”。

用户尚未修改时，可以写“跟着我重做一次”或展示“我准备怎样改”，并保留接下来真实操作的位置。制作安装演示时，区分压缩包已生成、安装到指定目录、客户端可发现、实际调用成功和陌生用户效果。
